# 项目发布到公网 —— 完整指南

> 整理自「零到全栈」模块 3.5，针对当前项目 `agent_lab` 部署到腾讯云服务器。

---

## 1. 整条链路长什么样

在脑子里先建一张图，后面每一步对应到图中的某一段：

```
你的电脑                GitHub                 云服务器               浏览器
─────────              ─────────              ─────────             ─────────
index.html  ──push──▶   agent_lab  ──pull──▶ ~/agent_lab ──▶   公网 IP
style.css                 仓库                   ↑
script.js                                     Nginx 把这个目录
                                              当作网站的内容
```

要做的事就是把中间两段连起来：
1. 让服务器从 GitHub 把代码 `pull` 下来
2. 让 Nginx 知道"网站内容在这个目录里"

## 3. 部署步骤

### 第 1 步：登录服务器

```bash
ssh ubuntu@101.33.225.107
```

> 登录成功后终端提示符变成 `ubuntu@xxx:~$`，说明已经在服务器上了。下面所有命令都在服务器上执行。

### 第 2 步：确认服务器上有 Git

```bash
git --version
```

Ubuntu 云镜像通常已预装 Git。如果看到 `command not found`：

```bash
sudo apt update
sudo apt install -y git
```

### 第 3 步：让服务器和 GitHub 之间建立 SSH 信任

> ⚠️ 每一台机器都需要自己的一对 SSH key。你电脑上的那对不能搬到服务器上用。

**生成 SSH key：**

```bash
ssh-keygen -t ed25519 -C "你的邮箱"
```

一路回车。完成后 `~/.ssh/` 里会生成两个文件：
- `id_ed25519` —— 私钥（绝不外传）
- `id_ed25519.pub` —— 公钥（下一步要用）

**把公钥加到 GitHub：**

```bash
cat ~/.ssh/id_ed25519.pub
```

复制输出的整行内容（以 `ssh-ed25519` 开头）→ GitHub 右上角头像 → **Settings** → **SSH and GPG keys** → **New SSH key** → Title 填 `腾讯云服务器`，Key 粘贴公钥 → 保存。

**验证连通：**

```bash
ssh -T git@github.com
```

首次连接输入 `yes`。看到 `Hi 你的用户名! You've successfully authenticated` 就说明通了。

### 第 4 步：把代码 clone 到服务器

```bash
cd ~
git clone git@github.com:3361880969LXY/agent_lab.git
```

> - 用的是 SSH 地址（`git@github.com:...`），以后 `git pull` 不需要输密码
> - 不需要 `sudo`，家目录是当前用户自己的地盘
> - clone 之后服务器上路径是 `/home/ubuntu/agent_lab`

验证一下：

```bash
ls ~/agent_lab/StudyRecord/agent-lab/front_code
```

应该看到 `index.html`、`style.css`、`script.js`。

### 第 5 步：看懂 Nginx 的配置文件

Nginx 的配置入口是 `/etc/nginx/nginx.conf`。它里面最关键的两行：

```nginx
include /etc/nginx/conf.d/*.conf;
include /etc/nginx/sites-enabled/*;
```

这两行把其他配置文件"串"了进来。我们要改的是 `sites-enabled/default`。

看一下当前默认配置：

```bash
cat /etc/nginx/sites-enabled/default
```

去掉注释后，真正生效的就这几行：

```nginx
server {
    listen 80 default_server;
    listen [::]:80 default_server;

    root /var/www/html;
    index index.html index.htm index.nginx-debian.html;

    server_name _;

    location / {
        try_files $uri $uri/ =404;
    }
}
```

**逐行解释：**

| 配置 | 含义 |
|------|------|
| `server { ... }` | 定义一个网站。一个 server 块 = 一个网站 |
| `listen 80 default_server;` | 监听 80 端口（HTTP 默认端口） |
| `root /var/www/html;` | **最关键的一行**：告诉 Nginx 去哪里找文件 |
| `index index.html ...;` | 访问目录时，默认返回哪个文件 |
| `server_name _;` | `_` 是占位符，表示"什么域名都接" |
| `location / { try_files ... }` | 路由规则：找文件 → 找不到就 404 |

### 第 6 步：把 root 改成我们自己的目录

```bash
sudo vim /etc/nginx/sites-enabled/default
```

把 `root /var/www/html;` 改成：

```nginx
root /home/ubuntu/agent_lab/StudyRecord/agent-lab/front_code;
```

> vim 操作：`/root /var` 搜索定位 → `i` 进入插入模式 → 修改 → `Esc` → `:wq` 保存退出
> 必须加 `sudo`，因为这个文件归 root 所有。

### 第 7 步：检查配置 + 让 Nginx 重新加载

**语法检查：**

```bash
sudo nginx -t
```

看到 `syntax is ok` + `test is successful` 就说明没问题。**校验不通过就绝对不能 reload**，否则 Nginx 可能挂掉。

**重新加载：**

```bash
sudo systemctl reload nginx
```

没有输出就是成功。`reload` 是平滑加载，不中断正在处理的连接。

### 第 8 步：解决 404 问题（权限！）

改完配置后浏览器访问 `http://101.33.225.107`，大概率是 **404 Not Found**（或 403 Forbidden）。

这不是配置错了，是**权限问题**。

Nginx 是以 `www-data` 这个用户身份去读文件的（在 `nginx.conf` 第一行 `user www-data;` 定义的），不是你登录用的 `ubuntu`。

`www-data` 要读到 `/home/ubuntu/agent_lab/...`，必须能逐层穿过每一级目录：

```
/  →  home  →  ubuntu  →  agent_lab  →  StudyRecord  →  agent-lab  →  front_code  →  index.html
```

查一下卡在哪：

```bash
ls -ld /home/ubuntu
```

输出可能是 `drwxr-x---`，最后三位 `---` 表示"其他人"没有任何权限。`www-data` 就是"其他人"，在这一层就被挡住了。

**修复（只需要做一次）：**

```bash
sudo chmod o+x /home/ubuntu
```

- `o` = others（其他人，Nginx 的 `www-data` 属于这一类）
- `x` = 能进入这个目录（但列不出里面有什么，安全的）
- 因为我们只给了 `x` 没给 `r`，别人没法 `ls` 你的家目录

改完之后**刷新浏览器**，页面就出来了！

### 第 9 步：体验一次完整的更新流程

以后每次改代码让公网生效，标准三步骤：

**本地（你的电脑）：**

```bash
git add .
git commit -m "写清楚这次改了什么"
git push
```

**服务器（SSH 登录后）：**

```bash
cd ~/agent_lab
git pull
```

**浏览器：** 刷新页面。

> ⚠️ 服务器上的代码目录是 GitHub 的"镜像"，所有改动都应该在本地做，通过 push/pull 同步。**服务器上不要手动改文件。**

## 4. Nginx 常用命令速查

| 命令 | 作用 |
|------|------|
| `sudo nginx -t` | 检查配置文件语法 |
| `sudo systemctl reload nginx` | 平滑重载配置（不中断服务） |
| `sudo systemctl restart nginx` | 完全重启 Nginx |
| `sudo systemctl status nginx` | 查看 Nginx 运行状态 |
| `sudo systemctl stop nginx` | 停止 Nginx |
| `sudo systemctl start nginx` | 启动 Nginx |

---

## 5. 常见问题排查

| 问题 | 原因 | 解决 |
|------|------|------|
| 还是显示 Nginx 欢迎页 | 浏览器缓存 | `Ctrl + Shift + R` 强制刷新，或用无痕窗口 |
| 404 / 403 | `www-data` 读不到文件 | `sudo chmod o+x /home/ubuntu` |
| `nginx -t` 报错 | 漏了分号 `;` 或路径写错 | 根据错误提示的行号回去改 |
| `git pull` 报冲突 | 服务器上手改过文件 | `git checkout .` 丢弃本地改动，再 `git pull` |

## 6. Nginx 配置目录结构（Ubuntu）

```
/etc/nginx/
├── nginx.conf              ← 配置总入口，Nginx 启动只读这一个
├── sites-available/        ← 所有"写出来"的网站配置（草稿夹）
├── sites-enabled/          ← 当前"启用中"的网站配置（生效夹）
│   └── default → ../sites-available/default  （软链接）
├── conf.d/                 ← 额外的全局配置片段
├── mime.types              ← 文件扩展名 → MIME 类型映射表
├── snippets/               ← 可复用的配置片段
└── modules-available/ / modules-enabled/  ← 动态模块
```

## 7. 回答：链接 URL 只能是 `http://101.33.225.107` 吗？

**不，不是只能这样。** 当前 `http://101.33.225.107` 是最基础的访问方式，你还有这些选择：

### 方式一：绑定自己的域名（推荐）

买一个域名（阿里云/腾讯云都可以，几十块一年），把域名解析到 `101.33.225.107`：

1. 在域名服务商后台添加一条 **A 记录**
2. 主机记录填 `@`（或 `www`）
3. 记录值填 `101.33.225.107`
4. 等几分钟 DNS 生效

然后改 Nginx 的 `server_name`：

```nginx
server_name 你的域名.com www.你的域名.com;
```

之后别人就能用 `http://你的域名.com` 访问了。

### 方式二：配置 HTTPS（推荐）

有了域名之后，申请免费 SSL 证书（Let's Encrypt / 腾讯云免费证书），Nginx 里加上 443 端口监听，就能用 `https://你的域名.com` 访问。

### 方式三：使用 CDN

如果你想要更快的访问速度，可以在域名前面套一层 CDN（腾讯云 CDN、Cloudflare 等）。

### 总结

| 访问方式 | 格式 | 需要什么 |
|----------|------|----------|
| 纯 IP | `http://101.33.225.107` | 什么都不需要，现在就能用 |
| 域名 | `http://你的域名.com` | 买域名 + 加 DNS 解析 |
| HTTPS + 域名 | `https://你的域名.com` | 域名 + SSL 证书 |

> **当前阶段直接用 IP 访问就够了**，等功能完善、准备写到简历上的时候，再配上域名和 HTTPS。

## 8. 关键理解

部署完成之后，你应该能说清楚这些：

- **Nginx 在做什么**：监听 80 端口，接收 HTTP 请求，根据 `root` 指向的目录返回对应的文件
- **GitHub 在做什么**：代码的中转站，本地 push 上去，服务器 pull 下来
- **`git pull` 在做什么**：把远程仓库的最新代码拉到服务器本地
- **为什么第一次访问是 404**：Nginx 以 `www-data` 身份读文件，被 `/home/ubuntu` 的权限挡住了
- **Nginx 配置里每个字段的作用**：`server`、`listen`、`root`、`index`、`server_name`、`location`
